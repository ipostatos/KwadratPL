# Оценка качества локации (Варшава) — как это работает

`backend/geo.py` + `backend/routers/location.py`. Публичный бесплатный инструмент:
адрес или точка на карте → общий балл 0–100 + 4 категории + ближайшие объекты.
Только Варшава (bbox 52.08–52.38 / 20.82–21.30).

## Источники (бесплатные, без ключей)

| Что | Откуда | Кэш |
|---|---|---|
| Геокодинг адреса + подпись точки | Nominatim (OSM), ≤1 req/s глобально | 30 дней |
| POI: транспорт, магазины, школы, парки | Overpass API (3 зеркала, 2 круга ретраев) | 7 дней (сетка ~11 м) |
| Доп. слой: свежие коммерческие точки | Google Places (New), **опционально** | 14 дней |

Кладбища не запрашиваются вовсе (классическая ошибка «кладбище = зелёная зона» у
таких сервисов). Метро мерится до **входов** (`subway_entrance`), не до центра
платформы. SKM/WKD — `railway=station|halt`.

## Google Places: жёсткий блокер бюджета

Ключ `GOOGLE_PLACES_KEY` в `.env` (ТОЛЬКО там, в репо не хранить). Каждый живой
вызов инкрементит `places_usage` (SQLite, переживает рестарт); при достижении
`PLACES_DAILY_LIMIT` (100) или `PLACES_MONTHLY_LIMIT` (2500) слой молча
отключается до следующего дня/месяца — оценка продолжает работать на чистом OSM.
Free tier Nearby Search ≈ 5000/мес → даже полный месячный лимит бесплатен.
Рекомендация: в GCP Console ограничить ключ API «Places API (New)» + IP VPS,
поставить budget alert.

Places только **добавляет** отсутствующие в OSM точки инфраструктуры (дедуп: тот
же вид + то же имя или ближе 80 м = один объект); транспорт/школы/зелень — чистый
OSM (там он полнее).

## Формула (калибрована на живых точках 2026-07-20)

1. **Distance decay** — плавная S-кривая: полный вклад до comfort-дистанции,
   косинусное затухание до нуля на dmax. Никаких линейных «минус балл за метр».
2. **Плотность** — вклад вида = сумма затуханий ближайших объектов с убывающими
   весами (1, 0.4, 0.25, …) / норма насыщения. Одна Żabka ≈ 70% вида «продукты»,
   вторая-третья добирают до 100%; одна станция метро = 100% вида (norm=1).
3. **Транспорт** (вес 0.40): 0.55·max(метро, 0.8·SKM) + 0.07·(оба) + 0.22·трамвай
   + 0.21·автобус. Comfort/dmax: рельсы 400/1300 м, остановки 250/700–900 м.
   Без рельсового транспорта потолок ~43.
4. **Инфраструктура** (0.25): продукты 0.32 (Żabka = полноценный вклад), аптеки
   0.14, еда 0.12, медицина 0.11, спорт 0.10, банки/почта 0.08, vet/площадки/ТЦ/
   базар 0.13. Нормировка /0.90.
5. **Школы и сады** (0.15): школы 0.58 (300/1200 м), сады 0.42 (300/900 м).
6. **Зелень** (0.20): парки/лес/скверы 300/1100 м; дистанция до центроида
   полигона — для больших парков консервативно завышена (честная погрешность).
7. **Итог** = взвешенная сумма × (0.70 + 0.30·худшая_категория/100) — провал
   одной категории не маскируется избытком остальных.
8. Вердикты: ≥80 excellent, ≥60 good, ≥40 average, <40 weak.

## Калибровка и стабильность

Бенчмарк живых точек (модель **1.1.0**, 2026-07-20): Centrum ≈ 97, Plac
Wilsona ≈ 99, Kabaty ≈ 84, Tarchomin ≈ 64, Saska Kępa ≈ 57, Stara Miłosna ≈ 41.

Процедура при ЛЮБОЙ правке констант скоринга:
1. Поднять `MODEL_VERSION` в geo.py (она отдаётся в ответе `/api/location/score`).
2. Прогнать calibrate-скрипт по бенчмарк-точкам (свежая temp-БД → без кэша).
3. Stability-чек: |новый − старый| ≤ 5 баллов на точку, если правка не была
   намеренной перекалибровкой именно этого сегмента; любой скачок объясняется
   письменно в коммите.
4. Обновить эту таблицу.

## Защита от парсинга (честная оценка)

- **Browser gate**: без Origin/Referer с наших страниц → 403 (отсекает наивный
  curl/requests; заголовки подделываются — это барьер, не криптография).
- **Per-IP лимиты**: score 20/час + 80/день, geocode 40/час + 160/день.
- **Глобальный дневной кап** живых Overpass-вызовов `GEO_DAILY_LIMIT` (400) —
  выкачивание города по сетке координат упирается в 503 `daily_capacity`
  (кэшированные ответы продолжают работать).
- CORS-allowlist: kwadratpl.pl, зеркало Vercel, localhost.
- Реальный потолок защиты публичного бесплатного инструмента — экономический:
  лимиты делают массовый съём медленнее, чем самостоятельный запрос в OSM.

## Геоданные объявлений (geo_enrich.py, Спринт 1 «почему подходит тебе»)

Фоновый цикл (каждые `ENRICH_INTERVAL`=300 с) обогащает варшавские объявления:

| Источник | Что даёт | precision |
|---|---|---|
| OLX | lat/lon из `offer.map` (точка рандомизирована в радиусе) | `approx` (реже `point`) |
| Otodom | улица из `location.address.street` → геокод | `address` (с № дома) / `street` |
| остальные | центроид района (18 шт., навсегда в кэше) | `district` |

Предрасчёт LocationQuality — **только** для `point/address/street` (скорить
рандомизированную точку OLX или центроид района и вешать бейдж = ложная
точность; для них в шторке кнопка открывает инструмент с пометкой
«приблизительно», `?prec=` на lokacja.html). Бюджеты: `ENRICH_GEOCODES`=25
геокодов/цикл, `ENRICH_SCORES`=15 оценок/цикл, `ENRICH_SCORE_DAILY`=120 живых
Overpass/день (плюс глобальный `GEO_DAILY_LIMIT` всё равно сверху). Результаты
в таблице `geo_listings`; в публичный listings.json их мерджит **инжест**
(файл вне инжеста не переписывается) → изменения видны на следующем прогоне
фетчера. Retention 60 дней.

## Env (все опциональны)

`GOOGLE_PLACES_KEY`, `PLACES_DAILY_LIMIT=100`, `PLACES_MONTHLY_LIMIT=2500`,
`GEO_DAILY_LIMIT=400`, `ENRICH_INTERVAL=300`, `ENRICH_GEOCODES=25`,
`ENRICH_SCORES=15`, `ENRICH_SCORE_DAILY=120`.

## API

- `GET /api/location/geocode?q=<адрес>&lang=ru|pl|ua|by|en` → `{results:[{label,lat,lon}]}`
  (пустой список = честное «не нашли»).
- `GET /api/location/score?lat=&lon=&lang=` → `{score, verdict, label, categories:
  {transport|infra|schools|green: {score, count, objects:[{name,kind,dist,lat,lon}]}},
  sources:["osm","google"?], cached, radius}`.
- Ошибки: 400 `outside_warsaw`, 403 `forbidden`, 429 `rate_limited`,
  503 `poi_unavailable` / `daily_capacity`.
